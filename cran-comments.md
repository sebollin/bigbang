## Update

This is a minor update from 0.5.1, published on 2026-10-06. It is submitted
sooner than usual because it fixes a data-safety defect:

- **Data-safety fix.** On R 4.1 to 4.5, a component archive containing a
  symbolic link followed by an entry written through that link could write
  outside the temporary extraction directory before bigbang rejected it, even
  with `dry_run = TRUE`. R 4.6.0 blocks this inside `untar()`, but older
  releases do not. bigbang now reads tar and ZIP archives with its own
  validating reader. It accepts only regular files and directories inside the
  destination, treats Windows junctions as links, rejects special entries,
  unsafe paths and inconsistent layouts, and enforces configurable size limits.
  It applies before any extraction in generation, diagnostics, local
  installation, artifact scanning and the installers of generated
  meta-packages.
- **The minimum R version is now 4.1.0**, which the imported glue has required
  since glue 1.8.1. A CI job now checks R 4.1.
- **Additive features:** `<meta>_deps(plan = TRUE)`, a read-only preview of an
  installation; `create_metapackage(governance = TRUE)`; and the option
  `bigbang.archive.portable_names`. Existing arguments keep their meaning. By
  default the reader also rejects file names that Windows cannot create, which
  0.5.1 accepted; the option accepts them outside Windows, with a warning.
