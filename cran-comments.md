## Update

This is an update from 0.4.0, published on 2026-08-19.

It fixes two defects of 0.4.0 that affect users of `reexport = TRUE`:

- A component that exported a name used by the generated installer, such as
  `getExportedValue`, made the generated meta-package unusable. Generated code
  now qualifies its calls to base functions.
- A meta-package could not be installed while an older version of a component,
  one that lacked a re-exported symbol, was installed: the final load test of
  `R CMD INSTALL` evaluates every re-export binding. Bindings now return a
  placeholder that explains the problem when it is called.

## What is new

- Collisions between components that export the same symbol are diagnosed and
  resolved explicitly with `reexport_prefer` or `reexport_exclude`. The error
  suggests a call that can be copied, and the installed owners are verified in
  a clean R process.
- `create_metapackage(update = TRUE)` keeps a durable journal beside the
  project, so an update interrupted even by `kill -9` is rolled back or
  completed by the next call. An exclusive lock prevents concurrent updates, and
  the new argument `recover` resolves states whose owner cannot be proven alive.
  Updates can now add components and change component versions.
- New arguments are added at the end of the signature. `NEWS.md` lists every
  breaking change with its migration.
